Building PyPhysics2D: Developing a 2D Physics Engine from Scratch in Python

November 22, 2026 Sai Satyam Jena

Introduction

Physics engines are an essential part of modern game development, scientific visualization, and interactive simulations. They allow virtual objects to behave according to physical principles such as gravity, velocity, acceleration, momentum, and collision response.

Instead of relying on an existing physics library, I decided to explore how these systems work internally by developing PyPhysics2D, a two-dimensional physics engine written in Python.

The objective was to build the fundamental components of a physics simulation from scratch, understand the mathematics behind them, and create an interactive environment in which the engine could be tested.

The project uses Python for the physics implementation and Pygame for visualizing the simulation.

1. Mathematical Foundation: Vector Mathematics

A physics simulation requires a mathematical representation of quantities that have both magnitude and direction.

For this purpose, PyPhysics2D implements a custom Vector2 class.

A two-dimensional vector is represented as:

[
\vec{v} = (v_x, v_y)
]

where (v_x) and (v_y) represent its horizontal and vertical components.

The vector implementation supports fundamental operations, including:

  • Vector addition and subtraction

  • Scalar multiplication and division

  • Magnitude calculation

  • Normalization

  • Dot product

The magnitude of a vector is calculated using:

[
|\vec{v}| = \sqrt{v_x^2 + v_y^2}
]

Normalization produces a unit vector pointing in the same direction:

[
\hat{v} = \frac{\vec{v}}{|\vec{v}|}
]

These operations form the mathematical foundation for calculating movement, forces, collision directions, and other physical quantities.

2. Rigid-Body Representation

The next component is the physical body itself.

Each body maintains properties that describe its physical state:

  • Position

  • Mass

  • Velocity

  • Acceleration

  • Applied force

  • Collision radius

  • Static or dynamic state

The engine uses Newton's second law of motion:

[
\vec{F} = m\vec{a}
]

Rearranging the equation gives:

[
\vec{a} = \frac{\vec{F}}{m}
]

This allows the engine to calculate acceleration from the total applied force and the body's mass.

A dynamic body responds to forces, while a static body remains stationary and behaves as an immovable object during simulation.

The project also includes rectangular bodies, extending the basic body representation with width, height, and bounding information.

3. Integrating Motion Over Time

A computer simulation does not calculate motion continuously. Instead, it updates the physical state at discrete time intervals.

PyPhysics2D uses a numerical integration approach to update velocity and position.

The implementation uses semi-implicit Euler integration:

\vec{v}_t + \vec{a}_t\Delta t
]

\vec{x}t + \vec{v}{t+\Delta t}\Delta t
]

Here:

  • (\vec{v}) represents velocity.

  • (\vec{a}) represents acceleration.

  • (\vec{x}) represents position.

  • (\Delta t) represents the time interval.

Gravity is implemented as an acceleration that continuously affects dynamic bodies.

The physics world also uses a fixed-timestep accumulator. Rather than allowing the physics calculations to depend directly on the rendering frame rate, the world advances through consistent simulation steps.

This helps make the simulation more predictable across different rendering conditions.

4. Collision Detection

Collision detection determines whether two objects overlap.

The engine implements collision handling for different combinations of circular and rectangular bodies.

Circle-to-circle collision

For two circles, collision detection uses the distance between their centers.

If the distance between the centers is smaller than the sum of their radii, the circles overlap.

[
d < r_1 + r_2
]

where (d) is the distance between the centers and (r_1), (r_2) are the radii.

Rectangle-to-rectangle collision

Rectangular bodies use Axis-Aligned Bounding Box (AABB) collision detection.

This method compares the minimum and maximum coordinates of two rectangles to determine whether their bounding regions overlap.

Circle-to-rectangle collision

For circle-rectangle collisions, the closest point on the rectangle is calculated and compared with the circle's center.

This allows the engine to detect collisions between circular objects and rectangular platforms.

5. Collision Resolution

Detecting a collision is only part of the problem. The engine must also calculate how objects should respond.

PyPhysics2D uses impulse-based collision response.

The relative velocity of two bodies is examined along the collision normal. When the bodies are moving toward each other, an impulse is calculated to modify their velocities.

For a simplified collision between two bodies, the impulse magnitude is:

[
j =
-\frac{(1+e)(\vec{v}_{rel}\cdot\hat{n})}
{\frac{1}{m_1}+\frac{1}{m_2}}
]

where:

  • (e) is the coefficient of restitution.

  • (\vec{v}_{rel}) is the relative velocity.

  • (\hat{n}) is the collision normal.

  • (m_1) and (m_2) are the masses.

The impulse is applied in opposite directions to the two bodies.

The engine also implements positional correction. This helps separate overlapping objects and reduces the possibility of objects remaining embedded inside one another.

6. The Physics World

The World class manages the simulation.

It maintains a collection of bodies and is responsible for:

  • Applying gravity.

  • Updating physical bodies.

  • Processing collisions.

  • Handling world boundaries.

  • Managing fixed simulation steps.

  • Adding and removing bodies.

Separating world management from individual body classes keeps the architecture modular.

The physics calculations are also separated from the Pygame visualization. This makes the engine easier to understand, maintain, and extend.

7. Building the Interactive Sandbox

To observe the engine in action, I developed an interactive Pygame sandbox.

The environment contains dynamic circular objects, static rectangular platforms, and world boundaries.

The sandbox allows the simulation to be controlled using the keyboard:

KeyFunction
SPACEPause or resume simulation
RReset the simulation
ESCExit the application

This environment provides a practical way to observe gravity, object movement, and collision responses.

8. Testing and Verification

Testing was an important part of development.

The project contains manual test scripts for individual components and an automated test suite using Python's built-in unittest framework.

The automated tests cover areas such as:

  • Vector operations

  • Force and movement calculations

  • Static-body behaviour

  • Circle collision

  • Circle-rectangle collision

  • AABB collision detection

  • World gravity

  • Adding and removing bodies

The automated tests can be executed with:

python -m unittest discover -s tests -p "test_physics.py" -v

Testing individual components makes it easier to identify problems before they affect the complete simulation.

9. Project Architecture

The project follows a modular structure:

│
├── physics/
│   ├── __init__.py
│   ├── vector.py
│   ├── body.py
│   ├── rectangle.py
│   ├── collision.py
│   └── world.py
│
├── tests/
│   ├── __init__.py

│   └── manual test scripts
│
├── main.py
├── requirements.txt
├── README.md
├── LICENSE
└── .gitignore

Each module has a specific responsibility, keeping the code organized and making future development easier.

10. Future Development

The current implementation establishes the basic structure of a two-dimensional physics engine. However, there are several areas that could be explored further.

Potential improvements include:

  • More advanced friction modelling.

  • Rotational dynamics and angular velocity.

  • Polygon collision detection.

  • Improved collision stability.

  • Spatial partitioning for larger simulations.

  • Additional physical constraints and joints.

These improvements would help move the project toward a more complete rigid-body simulation system.

Conclusion

Developing PyPhysics2D was an opportunity to explore the relationship between mathematics, programming, and physical simulation.

The project brought together vector mathematics, Newtonian mechanics, numerical integration, collision detection, and software architecture in one practical implementation.

More importantly, building the engine from scratch provided a better understanding of what happens behind the scenes when objects move, collide, and interact in a virtual environment.

PyPhysics2D is an ongoing learning and engineering project, and its current implementation provides a foundation for further experimentation with computational physics and simulation systems.
