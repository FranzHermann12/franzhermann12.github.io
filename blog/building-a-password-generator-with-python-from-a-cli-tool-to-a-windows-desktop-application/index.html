Building a Password Generator with Python: From a CLI Tool to a Windows Desktop Application

November 14, 2026 Sai Satyam Jena

1. Introduction

The Password Generator project started as an experiment in Python programming. I wanted to build something practical that could go beyond generating a random string of characters.

The initial idea was relatively simple: create a customizable password generator that allows users to control password length, character types, and other generation options.

However, I eventually wanted to turn it into a complete desktop application, with a graphical interface, configuration profiles, password analysis, and a proper Windows executable.

The result is Password Generator, a Python-based desktop application built using Tkinter.

The current version, 1.5.0, combines a customizable password generation engine with a classic Windows desktop interface.

2. Choosing Python and Planning the Architecture

I chose Python because it provides useful built-in modules for random generation, string manipulation, configuration management, and graphical application development.

For the graphical interface, I selected Tkinter.

One of the first architectural decisions was to separate the application into independent Python modules.

Rather than putting the entire program inside one file, I divided the responsibilities:

  • generator.py handles password generation.

  • config.py manages application settings.

  • profiles.py manages saved configuration profiles.

  • strength.py handles password strength analysis.

  • validator.py handles validation.

  • gui.py contains the graphical interface.

  • main.py provides the application entry point.

This modular approach made it easier to develop and modify individual components without unnecessarily affecting the rest of the application.

3. Developing the Password Generation Engine

The generation engine is the core of the application.

I wanted users to have control over how passwords are generated rather than relying on a fixed character set.

The generator supports four main character categories:

  • Uppercase letters (A–Z)

  • Lowercase letters (a–z)

  • Numbers (0–9)

  • Symbols

Users can enable or disable these categories according to their requirements.

The application also supports custom character selection, excluded characters, and required characters.

Why I used Python's secrets module

One important implementation decision was choosing the right random number generation method.

Python provides different approaches to generating random values. For this application, I used the built-in secrets module.

Unlike the conventional random module, which is designed primarily for general-purpose pseudorandom operations, secrets is specifically intended for generating values suitable for security-sensitive applications.

This makes it a more appropriate choice for password generation.

Character pool construction

The generator builds a character pool based on the selected options.

For example, if uppercase letters, lowercase letters, and numbers are enabled, those character groups are combined into a pool from which password characters can be selected.

The engine then applies the user's exclusions and custom character preferences.

This approach allows the same generation engine to support several different configurations without requiring separate generation algorithms for each preset.

4. Customization and Character Constraints

One of the features I wanted to implement was greater control over the generated output.

A basic generator usually provides only a length setting and a few character checkboxes.

I wanted to go further.

Universal customization in this project includes:

Custom symbols: Users can specify which symbols should be available during generation.

Excluded characters: Particular characters can be removed from the available character pool.

Required characters: Users can specify characters that must appear in generated passwords.

Similar characters: An option excludes visually similar characters such as I, l, 1, O, and 0.

Ambiguous characters: Another option excludes characters that can be difficult to distinguish or read.

The generation engine also validates its configuration before generating passwords.

The supported password length is 8–256 characters, and the application supports generating multiple passwords in a single operation.

These checks help prevent invalid configurations from reaching the generation process.

5. Password Presets

Configuring every generation option manually can become repetitive.

To address this, I implemented presets.

The application includes:

  • Standard

  • Strong

  • PIN

  • Easy Read

  • Custom

Each preset provides a convenient starting configuration.

The Custom preset allows users to work with their own settings.

This makes the application more convenient for different password-generation requirements without removing the ability to control individual options.

6. Password Strength Analysis

Generating a password is only one part of the application.

I also wanted to provide users with information about the characteristics of their generated passwords.

For this, I developed a separate password strength analysis component.

The analyzer uses theoretical entropy estimates based on password length and the size of the available character pool.

A simplified entropy calculation is:

[
H = L \times \log_2(N)
]

Where:

  • (H) represents the theoretical entropy in bits.

  • (L) represents password length.

  • (N) represents the number of possible characters in the selected character pool.

For example, increasing the password length or expanding the available character pool increases the theoretical number of possible combinations.

The application provides strength classifications:

  • Weak

  • Moderate

  • Strong

  • Very Strong

The analysis is intended as an estimate rather than a guarantee of real-world password security. Actual security also depends on factors such as randomness, exposure, and how a password is used.

7. Building the Graphical Interface

The graphical interface was one of the most visually important parts of the project.

I wanted to avoid the appearance of a generic modern application.

Instead, I chose a classic Windows desktop design.

The interface uses Tkinter and follows a traditional desktop application layout.

The main window contains five sections:

Generate: The primary password generation interface.

Customize: Additional controls for character selection and generation settings.

Profiles: Manage saved configurations.

Analysis: View password strength information and theoretical entropy estimates.

Settings: Configure application preferences.

I also implemented features such as showing and hiding generated passwords and copying generated results to the clipboard.

The final design was intended to feel like a traditional Windows utility while retaining the functionality of a more advanced password generator.

8. Configuration and Profile Management

Another important part of the application was making settings persistent.

I did not want users to configure everything again whenever they launched the program.

For this, I used JSON-based configuration files.

The application stores general settings in:

password_generator_config.json

Saved configuration profiles are stored separately in:

password_generator_profiles.json

The configuration system uses Python's dataclasses and JSON serialization to represent and save application settings.

The profile system allows users to save, load, and delete their preferred generation configurations.

Separating settings from the generation engine also makes future changes easier to implement.

9. Testing and Validation

As the project became more complex, testing individual components became increasingly important.

I created a separate test suite using Python's built-in unittest framework.

Some of the areas covered include:

  • Invalid password lengths.

  • Generating multiple passwords.

  • Excluding similar characters.

  • Excluding ambiguous characters.

  • Required character categories.

  • Invalid generation configurations.

I used the following command to execute the tests:

python -m unittest discover -s tests -v

The tests helped verify that the generation engine behaved correctly under different configurations.

I also had to address various issues during development, including GUI errors, configuration handling, and packaging problems.

10. Packaging the Application for Windows

Once the application was working as a desktop program, I wanted to make it distributable.

For this, I used PyInstaller.

The project includes a PyInstaller specification file named PasswordGenerator.spec.

The application can also be built using:

python -m PyInstaller --onefile --windowed --name PasswordGenerator gui.py

The resulting executable is placed inside the dist directory.

This allows users to launch the application without manually running its Python source files.

12. Conclusion

Password Generator evolved from a relatively simple Python project into a more complete desktop application.

Throughout development, I worked on several different aspects of software engineering, including modular architecture, random generation, input validation, configuration management, graphical interface development, automated testing, and application packaging.

One of the most interesting aspects was learning how to connect these individual components into a single working application.

The project also demonstrated the importance of separating the underlying logic from the graphical interface.

With version 1.5.0, Password Generator provides a customizable generation engine, configuration profiles, theoretical strength analysis, and a traditional Windows desktop experience.

It remains an ongoing project that can be extended with additional functionality and improvements.
